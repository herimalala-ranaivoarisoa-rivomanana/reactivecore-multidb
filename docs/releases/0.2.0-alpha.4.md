## ReactiveCore MultiDB 0.2.0-alpha.4

- Use a commit clock per tenant. Existing mutation receipts retain their original sequence.
- Schedule journal pruning and receipt response compaction. Subscriptions refresh after a pruned cursor, and retries of compacted receipts return HTTP 410 without applying the mutation again.
- Accept the first SSE snapshot after reconnecting, including when a restored database returns the same sequence. Redis notifications carry change metadata without application row images.
- Track dependencies and successful UUID-based writes automatically through the structured `ctx.data` interface. MySQL 8.4 remains a preview. Validation on Neon and Amazon RDS is pending.

The GitHub prerelease includes a Linux amd64 Docker image, a TypeScript SDK archive, and SHA-256 checksums. Apply the database migrations before starting the new runtime against an existing deployment. [Upgrade and retention guide](https://github.com/herimalala-ranaivoarisoa-rivomanana/reactivecore-multidb/blob/v0.2.0-alpha.4/OPERATIONS.md#upgrade-to-tenant-commit-clocks)
